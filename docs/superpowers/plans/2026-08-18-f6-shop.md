# F6 — Shop · Piano di implementazione

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** La coppia compra temi colore con le monete condivise e li attiva — l'acquisto applica subito il tema su entrambi i dispositivi in tempo reale, e un tema già posseduto si riattiva gratis in seguito, incluso il ritorno al default.

**Architecture:** Una tabella nuova (`owned_items`) e due funzioni Postgres `security definer` (`purchase_item`, generica e riusabile da F4; `select_theme`, specifica ai temi), che riusano `item_prices`/`spend_coins` già esistenti da F0+F1. Il frontend replica la forma di `features/questions/`: un livello di query dirette più RPC, un hook realtime, componenti che lo consumano. L'applicazione del tema è un secondo hook leggero (`useActiveTheme`) più un componente senza output visivo che imposta `data-theme` sull'`<html>`, letto da blocchi CSS aggiunti a `app/globals.css`.

**Tech Stack:** Stesso di F0+F1/F5 — Next.js App Router, TypeScript strict, `@supabase/supabase-js`, Vitest (unit in jsdom, integrazione contro Supabase locale).

**Spec di riferimento:** [`docs/superpowers/specs/2026-08-18-f6-shop-design.md`](../specs/2026-08-18-f6-shop-design.md)

**Branch:** `feature/f6-shop` (creato da `main`, che contiene già F0+F1 e F5 in produzione)

## Decisioni tecniche necessarie, non coperte dalla spec

1. **`item_prices` deve smettere di essere svuotata da `resetData()`.** Da F0+F1, `item_prices` era trattata come tabella di sola fixture per i test (svuotata a ogni `resetData()`), perché nasceva vuota e nessuna fase la seminava ancora — vedi `spend_coins.test.ts`, che la ripopola da zero in ogni `beforeEach`. F6 la semina con 4 righe **permanenti** (i temi, Task 4). Se `resetData()` continuasse a svuotarla, la prima chiamata di un qualunque test successivo nella stessa esecuzione (`fileParallelism: false` fa girare i file in sequenza sullo stesso database) cancellerebbe il catalogo reale — esattamente il bug già vissuto in F5 con `questions`, risolto lì con `cleanupQuestions`. Qui si previene proattivamente, nel Task 1: `item_prices` diventa seme permanente come `coin_rules`/`questions`, `resetData()` non la tocca più, e un nuovo helper `cleanupItems(keys)` rimuove chirurgicamente solo le righe di fixture create da un test — prima da `owned_items`, poi da `item_prices`, nell'ordine imposto dalla foreign key. `spend_coins.test.ts` va adattato nello stesso task per usarlo.
2. **`purchase_item` richiama `spend_coins`, non ne reimplementa la logica.** Il lock su `couple_state`, la lettura del costo da `item_prices`, la traduzione di `insufficient_funds`/`unknown_item` restano scritti in un solo posto, già testato in F0+F1. La genericità non è speculativa: il commento originale su `item_prices` la dichiara condivisa con F4.
3. **Le anteprime colore di `ThemeCard` sono un'eccezione dichiarata al vincolo "nessun colore letterale".** Quel vincolo esiste per evitare che un componente ignori il tema attivo; ma uno swatch che mostra com'è fatto un tema **non necessariamente attivo** deve mostrare colori letterali per definizione — non può dipendere dalle variabili CSS del tema corrente, che potrebbero essere quelle di un tema diverso. Vedi Global Constraints.

## Global Constraints

- Lingua dell'interfaccia: inglese. Commenti e documentazione in italiano.
- Mobile-first, viewport di riferimento 390 × 844 px. Ogni target di tocco almeno 44 × 44 px.
- Nessuna scrittura diretta dal client: solo `.select()` e `.rpc()`.
- Nessun colore letterale nei componenti, con una sola eccezione dichiarata: gli swatch di `ThemeCard` (Task 7), che rappresentano deliberatamente i colori di un tema che può non essere quello attivo. Ogni altro colore viene solo da variabili CSS di `app/globals.css`.
- TypeScript strict: nessun `any` implicito, nessun `@ts-ignore`.
- Ogni funzione Postgres nasce **senza** privilegio di esecuzione per nessuno: ogni funzione richiede il proprio `grant execute ... to authenticated` esplicito.
- Dopo ogni migrazione che aggiunge tabelle o funzioni, rigenerare `lib/types.ts` con `npm run db:types` e includerlo nel commit.
- Commit dopo ogni task, messaggio in italiano, prefisso convenzionale (`feat:`, `test:`, `fix:`).
- I 4 temi costano **100 monete ciascuno**, prezzo uniforme, seminati in `item_prices` (non in `coin_rules`: quella tabella è per i *guadagni*, questa per gli *acquisti*).

```sql
-- Generica, non specifica ai temi: pensata per essere riusata anche da F4
-- (skin degli animali), che condividerà item_prices/owned_items. Richiama
-- spend_coins invece di reimplementarne la logica: lock, lettura del costo e
-- traduzione di insufficient_funds/unknown_item restano in un solo posto.
create or replace function purchase_item(p_actor person, p_item_key text)
returns void
language plpgsql
security definer
set search_path = public
as $$
begin
  if exists (select 1 from owned_items where key = p_item_key) then
    raise exception 'already_owned';
  end if;

  perform spend_coins(p_actor, p_item_key);

  -- La violazione di unicità concorrente (due acquisti simultanei dello
  -- stesso oggetto) diventa already_owned, stesso pattern del
  -- round_already_open di F5: il controllo sopra è la via rapida per il
  -- messaggio giusto, questo vincolo è la vera rete di sicurezza.
  begin
    insert into owned_items (key) values (p_item_key);
  exception when unique_violation then
    raise exception 'already_owned';
  end;
end
$$;

revoke all on function purchase_item(person, text) from public, anon;
grant execute on function purchase_item(person, text) to authenticated;
```

```sql
-- Specifica ai temi. Attivare un tema già posseduto è gratis: comprare
-- (purchase_item) e attivare sono due passi distinti, così si può tornare a
-- un tema vecchio senza ripagarlo. 'default' è sempre permesso: non è mai

create or replace function select_theme(p_theme_key text)
returns void
language plpgsql
security definer
set search_path = public
as $$
begin
  if p_theme_key <> 'default' and not exists (
    select 1 from owned_items where key = p_theme_key

    raise exception 'theme_not_owned';

  update couple_state set theme = p_theme_key, updated_at = now() where id = 1;
```

```ts
import type { SupabaseClient } from '@supabase/supabase-js';
import { getSupabase } from '@/lib/supabase/client';
import { call } from '@/lib/rpc';
import type { Database } from '@/lib/types';
import type { Person } from '@/features/auth/identity';

export type ShopState = {
  /** Chiave item_prices → costo. Solo le chiavi che iniziano con "theme_". */
  prices: Record<string, number>;
  /** Chiavi possedute dalla coppia. */
  owned: string[];
  /** couple_state.theme corrente. */
  activeTheme: string;
};

type Client = SupabaseClient<Database>;
const db = (client?: Client): Client => client ?? getSupabase();

export async function fetchShopState(client?: Client): Promise<ShopState> {
  const c = db(client);

  const { data: prices, error: pricesError } = await c
    .from('item_prices')
    .select('key, cost')
    .like('key', 'theme_%');
  if (pricesError) throw new Error(pricesError.message);

  const { data: owned, error: ownedError } = await c.from('owned_items').select('key');
  if (ownedError) throw new Error(ownedError.message);

  const { data: state, error: stateError } = await c
    .from('couple_state')
    .select('theme')
    .eq('id', 1)
    .single();
  if (stateError) throw new Error(stateError.message);

  return {
    prices: Object.fromEntries((prices ?? []).map((p) => [p.key, p.cost])),
    owned: (owned ?? []).map((o) => o.key),
    activeTheme: state.theme,
  };
}

export async function purchaseItem(person: Person, key: string, client?: Client) {
  return call(db(client).rpc('purchase_item', { p_actor: person, p_item_key: key }));
}

export async function activateTheme(key: string, client?: Client) {
  return call(db(client).rpc('select_theme', { p_theme_key: key }));
}
```

```tsx
'use client';

import { useEffect } from 'react';
import { useActiveTheme } from '@/features/shop/useActiveTheme';

/**
 * Nessun output visivo: applica il tema condiviso all'intera app impostando
 * data-theme sull'elemento <html>. 'default', o il tema non ancora caricato
 * (null, al primo render), non impostano nulla: è già l'aspetto di base
 * definito in :root, nessun blocco [data-theme] serve per rappresentarlo.
 */
export function ThemeApplier() {
  const theme = useActiveTheme();

  useEffect(() => {
    if (theme && theme !== 'default') {
      document.documentElement.dataset.theme = theme;
    } else {
      delete document.documentElement.dataset.theme;
    }
  }, [theme]);

  return null;
}
```

```tsx
  active: boolean;
  who: Person;
}) {
  const [busy, setBusy] = useState<'buying' | 'activating' | null>(null);
  const [error, setError] = useState<string | null>(null);
  // Stessa guardia sincrona di QuestionCard/CategoryPicker (F5): il
  // `disabled` da solo non basta fra due tocchi molto ravvicinati.
  const sending = useRef(false);

  async function buy() {
    if (sending.current || cost === undefined) return;
    sending.current = true;
    setBusy('buying');
    setError(null);
    const { error: purchaseFailure } = await purchaseItem(who, theme.key);
    if (purchaseFailure) {
      setBusy(null);
      sending.current = false;
      setError(purchaseFailure);
      return;
    }
    // Comprare applica subito il tema (README): due chiamate, ma un solo tap.
    setBusy('activating');
    const { error: activateFailure } = await activateTheme(theme.key);
    setBusy(null);
    sending.current = false;
    // Se l'attivazione fallisce, il possesso resta comunque registrato: la
    // card si aggiorna via realtime mostrando "Activate", pronta per un
    // secondo tap. Nessuna moneta persa, nessuno stato sporco.
    if (activateFailure) setError(activateFailure);
  }

  async function activate() {
    if (sending.current) return;
    sending.current = true;
    setBusy('activating');
    setError(null);
    const { error: failure } = await activateTheme(theme.key);
    setBusy(null);
    sending.current = false;
    if (failure) setError(failure);
  }

  return (
    <div className={styles.card}>
      <div className={styles.head}>
        <p className={styles.label}>{theme.label}</p>
        <div className={styles.swatches} aria-hidden>
          <span className={styles.swatch} style={{ background: theme.swatches.bg }} />
          <span className={styles.swatch} style={{ background: theme.swatches.surface }} />
          <span className={styles.swatch} style={{ background: theme.swatches.accent }} />
        </div>
      </div>

      {active && <p className={styles.activeLabel}>Active</p>}

      {!active && owned && (
        <button
          type="button"
          className={styles.action}
          onClick={activate}
          disabled={busy !== null}
        >
          {busy === 'activating' ? 'Activating…' : 'Activate'}
        </button>
      )}

      {!owned && (
        <button
          type="button"
          className={styles.action}
          onClick={buy}
          disabled={busy !== null || cost === undefined}
        >
          {busy === 'buying'
            ? 'Buying…'
            : busy === 'activating'
              ? 'Activating…'
              : `Buy for ${cost} coins`}
        </button>
      )}

      {error && (
        <p className={styles.error} role="alert">
          {error}
        </p>
      )}
    </div>
  );
}
```
